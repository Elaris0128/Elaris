# Elaris 重構模板規格

這份文件定義 `Elaris` 在重構成 ChatGPT 文字冒險架構後，每一類內容應該怎麼寫。

## 目標

所有內容分成三層：

- `world`: 世界觀事實
- `game`: 遊戲規則
- `scenarios`: 可直接遊玩的內容包

原則是同一份文件只做一件事，避免背景設定、規則、劇情鉤子混在一起。

## 世界資料模板

適用於地區、國家、聚落、組織、種族、人物、地標。

```md
# 標題

## Metadata
- id:
- type:
- region:
- parent:
- tags:
- status:

## Summary
一句到三句摘要。

## Core Facts
- 位置
- 性質
- 關聯勢力
- 關聯種族
- 關聯資源

## Details
### 地理 / 結構
### 歷史
### 政治 / 組織
### 文化 / 信仰
### 經濟 / 交通
### 生態 / 危險

## Key Characters
- 名稱: 身分與作用

## Quest Hooks
- 玩家可以在此遇到什麼事
- 可衍生哪些任務或事件

## Retrieval Tags
- 給 AI 檢索用的關鍵字
```

## 區域文件最低拆分

每個大地區至少拆成以下文件：

- `overview.md`: 整體介紹
- `geography.md`: 地形與相對位置
- `climate.md`: 氣候與天候
- `hydrology.md`: 河流、潮流、水脈
- `factions.md`: 地區主要勢力
- `settlements.md`: 聚落與城鎮清單
- `characters.md`: 重要角色索引
- `adventure-hooks.md`: 可玩的遭遇、任務入口

## 國家文件最低拆分

每個國家或政治實體至少拆成：

- `overview.md`
- `history.md`
- `politics.md`
- `military.md`
- `law-and-order.md`
- `trade-and-economy.md`
- `culture.md`
- `religion.md`
- `settlements.md`
- `landscapes.md`
- `characters.md`
- `quest-hooks.md`

## 遊戲規則模板

適用於能力值、背包、戰鬥、任務、稱號等系統。

```md
# 系統名稱

## Purpose
這個系統在遊戲中負責什麼。

## Inputs
- 會讀取哪些玩家狀態
- 會讀取哪些世界資料

## Rules
1. 規則一
2. 規則二
3. 規則三

## Resolution
- 成功怎麼判定
- 失敗怎麼判定
- 部分成功怎麼判定

## Outputs
- 數值改變
- 敘事結果
- 是否產生新事件

## AI Instructions
- ChatGPT 在什麼情況要引用這份規則
- 輸出時要顯示哪些欄位
- 不能做哪些事
```

## AI 回應格式模板

所有遊戲回合建議統一成：

```md
## 場景描述
兩到四段，描述目前環境、人物反應與局勢變化。

## 可行動選項
- 選項 A
- 選項 B
- 選項 C

## 狀態變化
- 地點:
- 時間:
- 生命 / 精神:
- 金錢:
- 關鍵道具:
- 任務更新:
- 關係或聲望變化:

## 系統提示
- 若有檢定，顯示檢定結果
- 若解鎖新資訊，指出來源
```

## Scenario 模板

適用於開局劇本、區域冒險包、任務鏈。

```md
# 劇本名稱

## Premise
玩家在這個劇本中的起點。

## Entry Conditions
- 需要的背景或條件

## Opening Scene
- 第一回合會發生什麼

## Key NPCs
- 名稱: 功能

## Main Conflict
- 核心問題

## Branches
- 玩家常見選擇
- 每個選擇會把遊戲帶往哪裡

## Failure States
- 劇本如何失敗

## Rewards / Consequences
- 報酬
- 名聲變化
- 世界狀態改變
```

## 第一批重構順序

1. `content/game/12-ai-play`
2. `content/game/01-character`
3. `content/game/10-quests`
4. `賽勒亞大陸 > 東境 > 阿瓦隆王國`
5. `開局劇本`

這個順序的原因是，先把 AI 的主持邏輯、玩家開局、任務驅動定下來，後面搬地區資料才會知道哪些資訊真的需要被檢索。
