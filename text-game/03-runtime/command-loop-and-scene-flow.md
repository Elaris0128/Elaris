# 指令循環與場景流程

這份文件定義第一版 Elaris 文字遊戲在執行時，玩家輸入與系統更新之間的固定循環。

## 核心理念
遊戲不是單純聊天，也不是純選單。

玩家可以自由輸入，但系統每回合都要落回同一個結構：
1. 讀玩家意圖
2. 判定目前場景狀態
3. 套用規則
4. 更新狀態
5. 再交回新的場景與可行動點

## 一個標準回合

### Step 1：玩家輸入
玩家輸入可以是：
- 自由文字
- 明確動作
- 問問題
- 與 NPC 對話
- 對環境互動
- 進入戰鬥或撤退

### Step 2：系統拆解意圖
系統要把輸入拆成：
- 行動類型
- 目標
- 使用的資源
- 可能風險
- 是否需要查證 / 查資料

建議的行動大類：
- 移動
- 觀察
- 對話
- 交涉
- 使用物品
- 使用能力
- 戰鬥
- 長行動
- 休整

### Step 3：載入場景狀態
系統讀取目前：
- 場景 id
- 地區
- 當前壓力
- 在場 NPC
- 可互動物件
- 可見出口
- 任務相關目標
- 時間

### Step 4：規則裁定
依目前狀態判定：
- 直接成功
- 代價成功
- 失敗但前進
- 失敗且壓力上升
- 進入戰鬥
- 進入長行動進度

### Step 5：更新狀態
要更新的欄位至少包含：
- 角色位置
- 場景狀態
- 任務進度
- 線索
- 關係
- 聲望
- 傷勢 / 狀態
- 背包變化
- 世界時間

### Step 6：輸出回應
輸出應分成三層：
1. 小說式場景回應
2. 規則結果
3. 玩家下一步可做的事

## 場景資料最低需求
每個場景至少要有：
- `scene_id`
- `region_id`
- `title`
- `summary`
- `pressure_type`
- `npcs_present`
- `interactive_points`
- `exits`
- `active_risks`
- `related_quests`

## 回合後的輸出模板

### 敘事層
用小說式語氣描述：
- 眼前變化
- 誰有反應
- 危險是否靠近

### 系統層
簡短列出：
- 你成功了什麼
- 你付出了什麼
- 哪些狀態改變了

### 行動層
停在玩家可做下一步的位置，例如：
- 繼續追問
- 檢查某個點
- 先撤退
- 接下委託
- 休整

## 場景切換條件
只有以下情況才切場景：
- 玩家明確移動
- 事件強制拖入新場景
- 戰鬥 / 追逐導致位置改變
- 長行動推進到下一節點

## 第一版不做的複雜功能
- 即時同時多場景模擬
- 多線隊伍拆分同步操作
- 真正沙盒全天候排程

## 與 AI 的分工
- 系統：
  - 決定狀態
  - 決定風險
  - 決定是否推進任務或時間
- AI：
  - 描寫畫面
  - 表現人物反應
  - 用自然語言把結果說出來
